## 1. Ground rules (07 §1, plus three contract rules)

1. **Server state is truth; flags gate everything new.** A flag that is off returns `404 {error:"Not found"}`, which is never shown as an error. Read `/api/me/features` first.
2. **Wire compatibility beats UI parity.** G0 ships before any flagged feature.
3. **Logic in `commonMain`.** Platform code only for sensors, notifications, the camera, the picker, secure storage, Wallet and calendar intents. ViewModels expose `StateFlow`, and nested state is updated with deep copies (`AI.md` §1–2).
4. **Port tests with the code.** Use the same fixture values as iOS and web; never re-derive them.
5. **Done** means:
   - the acceptance boxes are checked
   - unit tests are green
   - a ledger row is added (§13)
   - a device check is recorded where the row says so
6. 🆕 **Decoders are lenient, encoders are canonical.** Every cross-client payload (broadcasts, metadata, push data) is decoded leniently:
   - unknown keys are ignored
   - known aliases are accepted
   - one bad message never ends a collector

   Payloads are encoded in the canonical snake_case form from the fixture (§11 W-3).
7. 🆕 **No direct PostgREST writes for anything click-web has an API for.** Connections, encounters, check-ins and Places go through `/api/*`, so server-side enrichment (quality keys, `place_id`, insights opt-in, weather) applies on every platform (§6 G4-10).
8. 🆕 **Contract changes land in click-web first.** That means the route, `BACKEND_CONTRACT_MATRIX.md` and a fixture in `__tests__/fixtures/mobile/`. Then iOS and Android consume it. A mobile PR that invents a wire shape fails review.

**G4-7 sampling and send**
- **Start:** after a tap or QR result, **if the moment's fix was worse than 5 m**.
- **Sampling:**
  - up to **20 s**, with `PRIORITY_HIGH_ACCURACY` and a 1 s interval
  - **stop early** when:
    - linear-acceleration RMS is above **0.12 g for 3 consecutive seconds** (`TYPE_LINEAR_ACCELERATION`)
    - any fix has speed ≥ **0.8 m/s**
    - a fix reaches ≤ **5 m**
- **Accepting a refined fix:**
  - the best still fix must be ≤ **0.8 × the original radius**
  - its position is the **inverse-variance mean** of the agreeing fixes; its radius is the best fix's own
  - drop it if it disagrees with the original by more than the sum of the two radii
- **Hold:** keep readings until the flow confirms its connection IDs. Wait ≤120 s, with ≤20 de-duplicated IDs.
- **Send:**
  - `POST /api/connections/encounter-location {connection_ids, connection_moment, observed_at, gps_lat, gps_lon, gps_horizontal_accuracy_m}`
  - and, if a barometric fix arrived late, `POST /api/connections/encounter-altitude {…}` (= 07)
- **Timestamps:**
  - ISO-8601 with **milliseconds**
  - `connection_moment` must **exactly equal** `sensor_observation.connection_moment` (the server matches within ±2 ms)
- **Server windows:**
  - the moment must be ≤15 min old and ≤5 min in the future
  - `observed_at` must be −30 s…+60 s from the moment
  - accuracy must be in (0, 50] m, and 0,0 is rejected
- **The server only improves the caller's rows**, including a group tap's pair rows.
- **Failures are silent.** Nothing is sent if the flow is cancelled.
- **Runtime:** a `CoroutineWorker` with `setExpedited` for the send. Sampling runs in the foreground while the result screen is visible; continuing after the screen closes is **not** required.
- **UI:** the result's "Location ±N m" updates live.
- **Tests (ported from iOS):**
  - stillness detection
  - the inverse-variance mean
  - the disagreement rejection
  - the moment-equality invariant

  2. Unwrap it like an epoch key (`chat_id:"approval:{id}"`, `epoch:1`, `sender_device_id:"click-device-approval"`) to get a 32-byte nonce.
  3. `POST …/{id} {decision, approving_device_id, challenge_id, proof: base64(nonce)}`.
- **Errors:**
  - 403 `EMAIL_PROOF_REQUIRED` / `DEVICE_PROOF_INVALID` / `APPROVER_NOT_ALLOWED`
  - 404 `NOT_FOUND`
  - 409 `HISTORY_REQUEST_DECIDED`
  - 410 `HISTORY_REQUEST_EXPIRED` / `HISTORY_REQUEST_DEVICE_GONE`

**G7-1 new (waiting) device**
- After registering, call `GET …/history-requests?device_id=` → `own` and the new **`approvers[{label, last_seen_at}]`** (≤10).
- **Banner:** "Unlock older messages", with a list like "Approve on your Pixel 9 (active 2 min ago)".
- **Actions:**
  - "Ask again": `POST …/history-requests {device_id, reopen:true}`
  - "Email me a link instead": `POST …/{id}/email`; otherwise it is sent automatically after 3 min
- **Empty approvers:** go straight to the email copy.
- **After approval:** the existing `/history-backfill` pull runs (`ChatApiClientDeviceHistory.kt:61`).
