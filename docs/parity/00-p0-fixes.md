# 00: P0 fixes (bugs and privacy)

These defects turned up during the parity audit. Each one is a small, independent diff; ship them before the feature work. Paths are relative to `KMP/` or `AM/` (see [README](README.md)).

| # | Defect | Evidence | Fix | Acceptance |
|---|---|---|---|---|
| P0-1 | **Plaintext reply excerpts leak E2EE content to the server.** Replies put `reply_to_content` (the decrypted snippet) into `messages.metadata`. | `KMP/viewmodel/ChatViewModelSend.kt:135,430`, `ChatViewModelSendMedia.kt:183,232,331,373`, `HubChatViewModel.kt:384,531,638` | Send only `reply_to_id`. Rebuild the quote on-device from the loaded or cached message, as `iOS/Features/Chat/ChatMessageSheets.swift:333` (`ReplyThumbnail`) does. Keep reading `reply_to_content` from legacy rows for display only (`KMP/data/models/MessageReplyMetadata.kt:29-33`). | No outbound metadata contains `reply_to_content`. Unit test on the metadata builder. The quote still renders when the target is loaded, and shows "Original message" when it isn't. |
| P0-2 | **Push previews fall back to server plaintext**, and v2 (`e2e2:`) previews are never decrypted. | `AM/notifications/ClickFirebaseMessagingService.kt:165,175,241-265` | Remove the `preview_text` fallback. Decrypt v2 in-process using persisted epoch keys (see 04 §2). If decryption fails, show a generic label ("New message", or "📷 Photo" from `message_type`). | A v2 group message push shows decrypted text or a generic label, never `preview_text`. |
| P0-3 | **Hangout-confirm nudges are resolved without confirming.** Tapping the inbox banner marks the nudge `acted` and opens the chat; the hangout then expires unconfirmed. | `KMP/ui/screens/ConnectionsListView.kt:636-668`, `KMP/ui/components/InboxNudgeBanner.kt:59-61` | Interim: skip `hangout_confirm`, `wave` and `group_revival` nudges in the banner until 03 §B5 lands. Final: typed dispatch per 03 §B5. | Tapping a `hangout_confirm` banner never marks the nudge acted without calling `/api/hangouts/{id}/confirm` or `/decline`. |
| P0-4 | **Relationship-moment pushes go down the chat-message path.** They are gated by the message preference, titled "Someone", and can bump inbox state through `ChatPushInboxBridge`. | `AM/notifications/ClickFirebaseMessagingService.kt:44-52,156-200` | Add explicit branches for `anniversary`, `memory_prompt`, `hangout_confirm`, `wave` and `group_revival` (routing spec in 03 §B6). | None of the five types reach `applyChatMessagePush`. |
| P0-5 | **Ultrasonic Goertzel recurrence bug.** `s2 = s` assigns the *new* value, so `s1` is never tracked. Repeated-digit merging is also fragile, and Android-generated tokens can contain repeated or leading-zero digits. | `KMP/proximity/UltrasonicTokenCodec.kt:31-35,107-145`; `KMP/viewmodel/ConnectionViewModelProximity.kt:321` | Use the correct recurrence: `s0 = x + coeff*s1 - s2; s2 = s1; s1 = s0`, then compute power from `s1`/`s2`. Generate tokens with the iOS safe-token rules (no adjacent repeats; see `iOS/Core/Proximity/ProximityCodec.swift` and `click-ios/Docs/IN_PERSON_TEST_MATRIX.md`). | Unit test: synthesized tones for every digit decode correctly, including tokens like `1123` or `0500` if they are still allowed. In-person matrix passes for Android→Android and iOS→Android. |
| P0-6 | **The barometric context opt-in has no UI**, so barometric data is never collected. | `saveBarometricContextOptIn` has no caller; it is read at `KMP/viewmodel/ConnectionViewModelProximity.kt:326` and `KMP/App.kt:159` | Add a toggle under **Privacy → Encounter context**, next to the ambient-sound toggle, which moves there too (05 §B3). | The toggle persists, and after opt-in an encounter includes `exact_barometric_elevation_m` on devices with a barometer. |
| P0-7 | **Forwarding is unreachable and would fail anyway.** `ChatApiClient.forwardMessage` always returns a failure, `onForward` is never invoked, and `ForwardDialog` passes a connection ID as a chat ID. | `KMP/data/api/ChatApiClient.kt:1100-1107`; `KMP/ui/chat/ChatMessageBubble.kt:104`; `KMP/ui/chat/ChatLoadingAndDialogs.kt:178-221` | Remove the dead stub and dialog now. Rebuild per 04 §4. | No dead forward code paths remain. |
| P0-8 | **A locked Click Drop can be saved or shared from the long-press sheet**, and Edit is offered for non-text messages. | `KMP/ui/chat/MessageActionSheet.kt:264-300` (no `isDisposableRollLocked()` check); `KMP/ui/screens/ChatViewOverlays.kt:163` (`canEdit = isSent`) | Hide Save/Share while `isDisposableRollLocked()`. Set `canEdit` only for your own sent plain-text messages (not media, beacon, call_log or plan). This mirrors `iOS/Features/Chat/ChatView.swift:500-517`. | UI test or unit test on the action-availability function. |
